# v2.15.1 — Recuperação emergencial do boot

Status: **PUBLICADA EM PRODUÇÃO COMO RECUPERAÇÃO ESTÁVEL**.

## Relato real
No iPhone/Safari, v2.13/v2.14/v2.15 falharam antes do login com erros como:
- `JSON Parse error: Invalid escape character e`
- `Pacote interno inválido: Unexpected identifier 'prevace'. Expected '}' to end an object literal.`

## Causa confirmada
O problema não era apenas sessão/localStorage. A investigação server-side do snapshot `runtime-v213` confirmou:
- `gunzipSync`: `incorrect data check` — checksum/rodapé gzip inválido;
- após recuperar somente o deflate interno, o payload ainda falha em `JSON.parse` com `Bad escaped character in JSON`;
- o conteúdo JavaScript está fisicamente corrompido/misturado no meio do arquivo, com trecho ilegível próximo de `prevace`;
- portanto o snapshot `runtime-v213` não é uma fonte confiável e não pode ser reparado apenas com parser tolerante.

## Correção imediata
- A produção deixou de carregar `runtime-v213`.
- O boot v2.15.1 usa o último snapshot conhecido estável, `runtime-bundle` do commit `d1acbe87cc8c59a345c5d423d4dae9bf183ae7fa`.
- Esse snapshot foi validado server-side: 8 partes presentes, gzip íntegro, `JSON.parse` aprovado e JavaScript compilado com `new Function` após os patches de compatibilidade conhecidos.
- Sessão Supabase corrompida continua sendo limpa somente quando o token local específico não é JSON válido.
- Logo continua em cápsula de alto contraste.

## Prevenção obrigatória
1. Nunca publicar runtime compactado sem validar gzip/checksum, `JSON.parse` e compilação do JS em ambiente independente.
2. Não usar fallback `Function(...)` para mascarar JSON corrompido.
3. `READY`/HTTP 200 do HTML não significa boot funcional; validar o payload executável antes de promover.
4. Enquanto o novo runtime com recursos v2.13+ não for reconstruído de fonte limpa, manter produção no runtime estável.
5. As funcionalidades comerciais/comissões/estampas solicitadas continuam no banco/especificação, mas o runtime corrompido não deve voltar à produção. A reconstrução limpa deve partir da base estável e receber as features novamente, com validação antes do deploy.
