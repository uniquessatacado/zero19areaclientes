# v2.11 — Robustez de exclusões e auditoria

## Motivo
Ao excluir uma empresa, o banco retornou `z19p_audit_log_workspace_id_fkey`. O gatilho de auditoria tentava gravar um `workspace_id` que já estava sendo removido.

## Plano
- preservar o histórico de auditoria após excluir uma empresa;
- alterar `z19p_audit_log.workspace_id` de `ON DELETE CASCADE` para `ON DELETE SET NULL`;
- tornar `z19p_audit_row_change()` seguro para DELETE/cascatas: se o workspace pai já não existir, gravar `workspace_id = NULL` e preservar o UUID original/nome em metadata;
- revisar todas as FKs `z19p_*` envolvidas em exclusões para evitar problemas equivalentes;
- não alterar layout nesta etapa.

## Regra de prevenção
Auditoria de DELETE não pode depender de uma FK para uma linha que acabou de ser apagada. Antes de publicar operações destrutivas, revisar os `ON DELETE` das FKs relacionadas.
