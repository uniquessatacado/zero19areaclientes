# v2.14 — Hotfix de inicialização no iPhone

Status inicial: **pronto para validação e publicação**.

## Relato real
No iPhone/Safari, a v2.13 exibiu `Não foi possível iniciar o sistema` com `JSON Parse error: Invalid escape character e` antes do login. O logo também aparecia como uma cápsula branca vazia porque o boot dependia de uma imagem externa.

## Diagnóstico
- O snapshot `runtime-v213` foi reconstruído e o JSON compactado foi validado fora do navegador; o pacote em si é íntegro.
- O erro pode ocorrer antes/depois da execução do runtime quando o Safari encontra uma sessão Supabase persistida inválida/corrompida em `localStorage`.
- A v2.13 não fazia validação preventiva dessa sessão, então qualquer `JSON.parse` interno de sessão quebrava todo o boot e era apresentado como erro genérico.

## Correção
- Antes de iniciar o app, validar somente `sb-kedggjyerexnzmipaick-auth-token`.
- Se esse token existir e não for JSON válido, remover **somente** a sessão local corrompida. Nenhuma empresa, arte, orçamento, mídia ou dado de banco é apagado; no máximo o aparelho precisará efetuar login novamente.
- Se um erro de JSON escapar durante a primeira execução, limpar o mesmo token e recarregar uma única vez com guarda em `sessionStorage`, evitando loop.
- Logo oficial passa a ser servido como `/zero19-logo.svg` autocontido no próprio deployment, evitando dependência do Raw GitHub para a identidade visual.
- Interface interna mostra `v2.14`; páginas públicas não exibem versão.

## Não regressão
Todos os módulos da v2.13 permanecem preservados: catálogo/qualidades, portfólio, 100 MB, 1 vídeo + 3 fotos, curtidas, comentários, templates WhatsApp, integração com produtos/orçamento, estampas, criação de arte, comissões e divisão de comissão.

## Regra adicionada
Smoke test de produção deve validar boot em navegador real, não apenas HTTP 200/READY. Erro de sessão local nunca pode derrubar o aplicativo inteiro.
